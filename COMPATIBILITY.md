# Compatibility

Target: Manim Community 0.22.1. Current development version: 0.11.0-dev.

The public API inventory is `compatibility/api_inventory.json`; reviewed
declarations are in `compatibility/implemented.json`. `python3 tools/coverage.py`
validates declarations and writes `compatibility/summary.json`. Status labels:

- `implemented_verified`: the documented API has executed behavioral evidence.
- `implemented_partial`: actual functionality exists, with explicit restrictions.
- `not_implemented`: no implementation is claimed.
- `blocked`: an identified dependency subsystem is missing.
- `not_applicable`: only for a justified host-language difference; none is used
  to avoid implementing a scene capability.

The current inventory contains 5,155 explicit symbols. It includes module
`__all__` declarations, all public definitions, and
public class methods defined in those classes and uppercase constant assignment
declarations. Inherited methods resolve to the defining class. Runtime root
exports have a separate index in `compatibility/public_exports.json`.
Dynamic instance attributes still need a later audit.
These symbol counts are not a percentage of total project completion.

## Executable surface

Actual vector paths: VMobject, VGroup, Group, Arc, Circle, Dot, Ellipse, Line,
Polygon, RegularPolygon, Rectangle, Square, Triangle and CubicBezier. Transforms
include shift, scale, stretch, arbitrary-axis rotation, 2×2/3×3 matrices,
positioning, alignment, grouping, copying, stroke/fill style and z-order.

Actual animations: Create, Write, DrawBorderThenFill, FadeIn, FadeOut, Transform, ReplacementTransform,
Unwrite, Rotate, MoveAlongPath, AnimationGroup, Succession and LaggedStart. Builders use
`m:animate(options):shift(...)`. ValueTracker and callbacks execute in Lua.
Scenes provide add/remove/replace, play/wait, deterministic stepping and real
PNG/MP4/GIF/WebM rendering. All four formats have executed file decoding and
motion checks. PNG transparency has been checked; encoded-format alpha fidelity
needs further coverage.

Text now has real native Pango shaping and cubic outlines: font selection,
Unicode, multiline text, tabs, font size, BOLD/LIGHT weights, ITALIC/OBLIQUE
styles and ligature disabling. Thirteen text cases match upstream metrics
within 1e-4 scene units and image differences within the stated tolerance.
Pango now emits an in-memory SVG with individual glyph references, imported
through the native vector pipeline. The 13 original-upstream images and the
diagnosed RTL layout image now have zero pixel error in this environment.

One standalone RTL word produces an empty SVG in upstream because canvas-wide
automatic RTL alignment clips it outside the surface. luanimath renders it.
`tools/reference_text.py` retains the original empty output and diagnoses it
by changing only ManimPango's `pango_width` to 100, which restores the glyphs.
The corrected reference matches the native output. This is **one explicitly
recorded original-upstream mismatch**, not a passing original compatibility case.
Mixed LTR/Arabic text is separately checked against unmodified Manim.

SVG paths support M/L/H/V/C/S/Q/T/A/Z, absolute/relative commands, repeated
parameters, adjacent numbers and elliptical arcs. SVGMobject imports paths,
lines, rectangles, circles, ellipses, polygons and polylines; nested groups,
affine transforms, local `use` references, named/hex/RGB paints, fill/stroke
opacities and styling overrides. Seventy-three path cases, 24 imported object
cases and 12 actual reference images have executed differential coverage.
The images matched exactly in the recorded environment. SVG alpha quantization,
non-scaling strokes, root-viewBox/transform discard and ignored group `opacity`
follow the pinned upstream importer, including its quirks.

SVG remains partial: CSS stylesheets, HSL paints, gradients,
patterns, clipping/masks/filters, viewport/physical units, external references,
text/images inside SVG, file search and SVG caching are pending. Unsupported
drawing features raise errors; this importer does not claim full SVG compliance.
ID lookup covers named groups/shapes and root; upstream autogenerated numbered
groups and duplicate-ID lookup semantics are not yet reproduced.

## Current restrictions

MovingCamera and MovingCameraScene have an actual animated frame. ThreeDCamera
and ThreeDScene provide phi/theta/gamma orientation, focal distance, zoom,
projection, fixed overlays, depth ordering and tracked camera movement. The
native Cairo backend performs the two-stop lighting gradients used by Manim's
3D shading. Cube, Sphere, ThreeDVMobject and parametric Surface have executed
geometry and visual comparisons; seven moving-camera/3D reference frames,
including lit and unlit objects, matched pixel-for-pixel in this environment.
Surfaces retain upstream zero-based `u_index`/`v_index` metadata internally;
Lua sequence tables remain 1-based.

Numerical axes and graphs now include NumberLine, Axes, scalar/batched point
conversion, ticks, standard triangular 2D tips, ParametricFunction,
FunctionGraph and Axes.plot. Open and closed cubic splines use the upstream
linear-time tridiagonal/rank-one algorithms, with 83 differential cases and
12,264 scalar/invalid-input comparisons. `always_redraw` executes actual Lua
callbacks. Automatic math labels, custom tips and many specialized
plotting methods remain pending and are explicitly rejected where applicable.

- Transform aligns unequal vector families, empty vector groups, differing
  curve counts and multiple subpaths using upstream duplication/fade and null
  path rules. Non-vector point clouds and all malformed/degenerate cases are
  not yet covered. Curved arc/circular paths and custom path functions work.
- One RGBA fill and stroke per object. Family color gradients are real and
  opacity-preserving; spatial gradients/sheens and background strokes,
  several style inheritance options and path-building APIs are pending.
- Path builders support complete cubics and one pending start anchor, including
  lines, quadratic degree elevation, multiple subpaths, closing and subdivision.
  Incomplete two-/three-point cubic groups are rejected. Boundary queries on
  pending paths use the available anchor instead of reproducing upstream's
  inconsistent anchor-array zip failure.
- AnimationGroup/LaggedStart support backward interpolation and there-and-back
  rate functions. Succession remains forward stepping. Starting/target snapshots
  execute their actual updaters; grouped MoveAlongPath preserves the whole group.
  The complete option surface and every overlapping animation case still need work.
- Many constructor options are still pending; an implemented class name does
  not imply all its upstream arguments are implemented.
- Text contains individual glyph Mobjects and identity-sharing `chars` groups.
  Lua indexing/iteration includes the object itself when it has points, matching
  upstream’s conceptual sequence; indices are 1-based, negative indices count
  from the end, and out-of-range lookup returns nil. `slice` uses inclusive
  endpoints. Reverse Write and Unwrite have actual timing/order/cleanup tests.
  19 glyph cases, 42 animation states/images and three font resizing cases
  passed upstream comparison. Text now supports t2c/t2f/t2s/t2w/t2g, long-form
  aliases, Unicode word selectors, source bracket-selector syntax, gradients
  and overlap rejection. Twenty-one MarkupText cases and forty styled Text
  cases (including twenty seeded multi-style overlap cases) match upstream
  points/styles and images. Pango markup supplies nested font/size/color,
  decoration, scripts, multiline and justified layout.
  Bracket-selector strings preserve upstream’s zero-based/exclusive syntax;
  out-of-bounds ranges and empty selectors are rejected explicitly. Manim’s
  deprecated custom color/gradient markup tags, missing-font warnings, plain
  text wrapping and remaining constructor options are pending. Natural-width
  plain text layout retains the documented standalone RTL difference. Native
  markup currently uses upstream’s fixed 500-unit paragraph width and ignored
  positional line-spacing/tab-expansion behavior.

- Camera clipping at the focal plane, complete surface/camera options,
  per-point textures, subcameras, ambient rotation helpers and the remaining
  3D object families are pending. Points exactly on the focal plane are
  explicitly rejected. The 3D API remains partially compatible.
- TeX/MathTex, expression-matching transforms, raster images, advanced plots,
  remaining 3D features, OpenGL,
  audio, render caching, scene sections and notebook integration are pending.
- Lua 5.4 is the only tested ABI. Lua indices are 1-based. Tables and functions
  replace Python classes and keyword machinery where appropriate.

## Numeric and visual tolerances

Differential geometry, style and timing fixtures use absolute tolerance 1e-9.
SVG elliptic-arc tests use 1e-8 absolute tolerance because the source algorithm
passes through trigonometric radius correction and quadratic degree elevation.
Image comparisons require equal dimensions, mean absolute RGBA channel error
<=0.6 on [0,255], and at most 0.004 of pixels with any channel error >16.
These allow small Cairo edge-rounding variation without accepting displaced
geometry or changed object colors. Measured errors are recorded, never inferred.
The initial 30 frame pairs had zero pixel error in this environment.

Three-dimensional numerical comparisons use 1e-9 absolute plus 1e-14 relative
tolerance. The relative term is necessary for the upstream behind-focal-plane
sentinel projection factor of 1e6, which magnifies normal floating-point matrix
rounding into coordinates above 1e7. The seven 3D image tolerances are unchanged
from the existing visual suite and measured zero error. Ordinary 2D numerical
tolerances remain 1e-9 absolute.

No overall production-readiness or complete Manim compatibility is claimed.

## Mathematical typography

Typst and MathTypst compile through the native Typst 0.15.1 CLI, then use the
actual vector importer and renderer. Named/unnamed/nested/repeated captures,
ordinary Typst labels, source colors, font size, explicit size, source strokes,
affine baseline tracking, selection identity and copy independence execute tests.
Numeric selection is Lua 1-based. Typst syntax is distinct from LaTeX.

The corpus retains **44 original states/images**. In **six** states, upstream
SVG cache hits omit baseline/stroke tracking, changing scaling behavior. Lua
intentionally retains tracking on cached imports. The tests assert that this
original mismatch remains visible and compare separate diagnostic states made
by changing only `use_svg_cache=False`. There are 38 unmodified comparisons and
six separately diagnosed comparisons; neither set establishes complete parity.

Typst numeric comparisons use 1e-8 absolute tolerance for SVG-coordinate
imports and affine baseline fits; images use the existing pixel thresholds.

Cache keys cover source, compiler version, font-path strings and root, with
content checksums for generated SVG. They do not track external font/file
contents. Use `use_cache=false` or clear the cache after external changes.
Nonlinear baseline deformation, every Typst SVG feature and all constructor
options remain unverified. Unsupported SVG features raise importer errors.
MathTex/Tex and matching-expression transforms remain pending.

## Numerical scales

LinearBase and LogBase provide scalar/nested-array map/inverse methods. NumberLine
maps numerical values through the inverse scale, transforms ticks and retains
unscaled x_range plus scaled x_min/x_max/x_step metadata. Axes uses scaled bounds
for its origin placement and retains logarithmic origin ticks. ParametricFunction
scales sample times, including discontinuity exclusions; Axes.plot inherits the
x-axis scale. Transformed axes and graph sampling have executed upstream tests.

Linear factors must be finite/nonzero and log bases positive/different from 1.
All results must be finite; every logarithmic inverse input must be positive.
This deliberately rejects mixed invalid arrays that upstream can return as NaN.
Default/custom numeric label construction remains pending and include_numbers
is rejected. The retained custom_labels scale flag is metadata only. Numerical
zero has no logarithmic coordinate, so get_origin() rejects logarithmic axes.

## Color constants

All 89 constants/aliases in the pinned manim_colors module are exported as
immutable Lua RGB hex strings. Named parsing and normalized RGBA values are
verified against actual upstream values, with an executed 89-swatch image.
This covers constant values, not the unimplemented ManimColor class interface.
The inventory includes these 89 constant symbols separately from 217 other
available symbols; constant coverage must not be read as additional engine
features or overall implementation progress. YELLOW now follows #F7D96F;
PURE_YELLOW preserves #FFFF00. The previous small graph-image differences were
traced to that palette mismatch; corrected comparisons have zero pixel error.

## Circular and rounded geometry

ArcBetweenPoints, Polygram, RoundedRectangle, closed vertex groups and corner
rounding execute real cubic geometry. Circular-center queries use the first
cubic's XY tangent normals; nonplanar/undefined centers return ORIGIN and set
_failed_to_get_center. Signed radii, concave corners, clamped large corners,
per-corner radius sequences, anchor redistribution and elliptical SVG rx/ry
have actual oracle coverage. Radius-list length must divide each loop size.
Negative SVG radii and exact full-turn endpoint arcs are rejected; use Circle
for a full turn. Dense construction is limited to 100,000 curves.

Eleven original behavioral differences are retained, asserted and diagnosed:
one numerically spurious straight-arc center, six clamped-rounding cases where
ceil of roundoff adds degenerate curves, and four closed-circle endpoint
placements that amplify closure roundoff. Lua uses an undefined-center fallback,
avoids extra subdivision of gaps <=1e-12, and shifts closed loops. Normalized
geometry/shift diagnostics are separate from original parity. The actual eleven
rendered circular/rounded/SVG images match the original upstream pixels.
Numerical geometry uses 1e-9 absolute tolerance; no overall API completeness is
claimed from these cases.
